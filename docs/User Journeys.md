# DigestDesk — User Journeys

> 用户如何在 DigestDesk 中完成核心任务。
> 每条 Journey 标注了当前实现状态，便于对照开发进度。

## Journey 1：首次使用（Onboarding） `[未实现]`

> **当前状态：** 无引导流程。首次打开直接进入日报页面（DailyDigest），如果没有订阅源和文章数据则显示空状态。
> **对应代码：** `src/pages/DailyDigest.tsx`（首页/日报页）、`src/pages/Subscriptions.tsx`（添加订阅）

### 场景
用户第一次打开 DigestDesk，从零开始到看到第一份 Digest。

### 关键目标
**3 分钟内看到第一份 Digest。** 这是转化的关键节点。

### 流程

```
Step 1: 打开 DigestDesk
├── 看到欢迎页/引导
├── 简短说明："添加你的 Substack 订阅，AI 帮你编辑日报"
└── 主操作按钮："添加第一个订阅"

Step 2: 添加订阅
├── 方式 A：搜索关键词 → 选择出版物 → 确认
├── 方式 B：粘贴 Substack URL → 预览卡片 → 确认
├── 系统自动获取出版物信息（名称、Logo、简介）
├── 推荐："再加几个？" + 热门 Substack 推荐列表
└── 用户添加 3-5 个订阅

Step 3: 生成首份 Digest
├── 系统自动抓取最近 7 天的文章
├── AI 生成摘要
├── 展示加载动画："你的编辑正在阅读..."
└── 首份 Digest 呈现 ← 魔法时刻 ✨

Step 4: 设置推送（MVP 后）
├── 提示："要不要每天收到日报推送？"
├── 浏览器通知权限请求
├── 设置推送时间（默认 8:00）
└── 完成引导
```

### 设计要点

- Step 2 → Step 3 之间不能让用户等太久（首次可用过去 7 天数据增加丰满度）
- 搜索添加降低"不知道该订阅什么 URL"的门槛
- 推荐列表降低"不知道该订阅什么"的门槛
- 如果用户拒绝推送权限，不强求，引导他"每天来这里看"

### 可能的退出点

| 退出点 | 原因 | 应对 |
|--------|------|------|
| Step 2 不知道粘贴什么 | 不记得自己订阅了哪些 | 提供搜索功能 + 热门推荐 + "从邮箱导入"（未来） |
| Step 3 等待太久 | 首次生成慢 | 优化首次生成速度；显示进度/预估时间 |
| Step 3 摘要质量差 | AI 总结不到位 | 持续优化 prompt；收集反馈 |

## Journey 2：日常使用 — 阅读日报 `[已完成 ✅]`

> **当前状态：** 前后端已完整联调。DailyDigest 页面展示真实日报数据（TOC + 文章卡片），后端 RSS 抓取（Jina Reader + Turndown 兜底）、AI 摘要生成（gpt-5-nano + Zod schema）、日报生成 API 均已跑通。cron 每小时自动同步 RSS 并生成当日日报。归档切换、阅读完成仪式等交互均可用。
> **对应代码：** `src/pages/DailyDigest.tsx`（UI + 数据加载）、`server/src/services/digest.ts`（日报生成）、`server/src/services/summarizer.ts`（AI 摘要）

### 场景
用户已完成设置，每天早上查看日报（MVP 阶段手动打开，后续加推送）。

### 流程

```
Step 1: 打开日报（MVP：手动打开网页）
├── MVP：直接访问网页，进入 Digest 页面
├── 后续：浏览器通知推送 → 点击通知
└── 直达今日 Digest 页面

Step 2: 打开日报
├── 直达今日 Digest 页面
├── 顶部显示日期、文章数、预计阅读时长
└── TOC 目录列出所有文章

Step 3: 快速扫描（30秒）
├── 浏览 TOC 目录
├── 通过标题和来源判断感兴趣的内容
└── 点击感兴趣的条目跳转

Step 4: 阅读摘要（3-5分钟）
├── 阅读一句话总结 → 判断是否值得深入
├── 阅读关键洞察 → 获取核心信息
├── 如果足够了 → 继续下一篇
└── 如果想深入 → 点击"阅读原文"

Step 5: 完成阅读
├── 读完所有感兴趣的摘要
├── 关掉页面
└── 去做自己的事 ← 核心价值：5分钟搞定
```

### 设计要点

- MVP 阶段用户手动打开网页查看，无推送通知
- TOC 是"10 秒决策"工具：用户用 10 秒决定今天看哪几篇
- 摘要的信息密度要足够高：读完摘要 = 获取原文 80% 的价值
- "阅读原文"按钮始终可见但不强调（不是主要路径）

### 关键指标

- 从打开到开始阅读 <3 秒
- 平均阅读时长 3-5 分钟
- 原文点击率 20-30%

## Journey 3：日常使用 — 阅读周报 `[已完成 ✅]`

> **当前状态：** 前后端已完整联调。WeeklyDigest 页面展示真实周报数据（本周主题归纳 + 归档切换）。后端通过汇总本周日报的 oneLiner 摘要调用 AI 生成跨源主题归纳（`WeeklyAnalysisSchema`）。首次打开无周报时自动触发生成。
> **对应代码：** `src/pages/WeeklyDigest.tsx`（周报 UI + 数据加载）、`server/src/services/summarizer.ts`（周报 AI 分析）、`server/src/services/digest.ts`（周报生成逻辑）

### 场景
用户在周日晚上查看本周周报。

### 流程

```
Step 1: 打开周报（MVP：手动打开）
├── MVP：直接访问网页，切换到周报 Tab
├── 后续：推送通知"你的本周 Digest 已就绪 · 第 7 周"
└── 点击通知

Step 2: 打开周报
├── 顶部：本周概览（文章总数、覆盖源数）
├── 第一区域：本周热门主题（跨源归纳）
└── 第二区域：逐日回顾（可折叠）

Step 3: 阅读主题概览（2分钟）
├── "你关注的作者们本周集中讨论了：AI Agent、SaaS 定价..."
├── 快速了解行业趋势
└── 判断是否有遗漏的重要内容

Step 4: 回顾逐日内容（可选，5分钟）
├── 展开某一天的日报
├── 补看漏掉的内容
└── 可跳过

Step 6: 完成
├── 对本周信息有全局视角
└── 准备好下一周
```

### 设计要点

- 周报不是日报的简单汇总，而是更高层次的编辑产品
- "本周主题"是周报独有的价值：帮用户看到跨源的趋势
- 编辑推荐解决"我这周可能错过了什么"的焦虑
- 逐日回顾是补充，默认折叠，感兴趣再展开

## Journey 4：管理订阅 `[已完成 ✅]`

> **当前状态：** 前后端已完整联调。订阅管理页支持搜索添加（Substack 搜索 API 代理，300ms 防抖自动搜索）和 URL 添加（预览卡片确认）双入口。订阅列表展示 Logo、名称、作者，支持删除确认。已订阅的出版物在搜索结果中标注"已订阅"。
> **对应代码：** `src/pages/Subscriptions.tsx`（搜索/URL Tab UI）、`server/src/routes/substack.ts`（搜索 + 信息 API）、`server/src/routes/feeds.ts`（CRUD API）

### 场景
用户想添加新的 Substack 订阅，或删除不再需要的订阅。

### 添加订阅 — 路径 A：搜索添加

```
Step 1: 进入订阅管理页
├── 侧边栏点击"订阅源"
└── 看到当前所有订阅列表

Step 2: 搜索添加
├── 切换到"搜索添加" Tab
├── 输入关键词（作者名、主题、出版物名称）
├── [Loading] 系统调用 Substack 搜索 API
├── 展示搜索结果列表：Logo、名称、简介
├── 用户点击想要的出版物 → 确认订阅
├── Toast："订阅成功，将在下一份日报中包含"
└── 列表更新
```

### 添加订阅 — 路径 B：URL 添加

```
Step 1: 进入订阅管理页
├── 侧边栏点击"订阅源"
└── 看到当前所有订阅列表

Step 2: URL 添加
├── 切换到"URL 添加" Tab
├── 输入框粘贴 Substack URL
├── [Loading] 系统获取出版物信息
├── 显示预览卡片：名称、Logo、简介、最近更新时间
├── 用户点击"确认订阅"
├── Toast："订阅成功，将在下一份日报中包含"
└── 列表更新
```

### 删除订阅

```
Step 1: 在订阅列表中找到目标
Step 2: 点击删除按钮
Step 3: 确认对话框："确定取消订阅 [Lenny's Newsletter] 吗？"
Step 4: 确认 → Toast："已取消订阅"
```

### 设计要点

- **搜索优先**：搜索 Tab 默认选中（降低"不知道 URL"的门槛）
- 搜索结果展示 Logo、名称、简介（帮用户确认"这就是我要的"）
- URL 添加作为备选，支持多种格式容错
- 添加订阅必须展示预览信息
- 删除需要确认（防误操作），但不要过度警告

## Journey 5：无新内容时 `[部分实现]`

> **当前状态：** 已实现基础空状态处理。无订阅源时显示引导添加卡片（带跳转按钮）；有订阅源但无日报时显示提示文案。尚未实现：显示最近一期日报供回顾、"添加更多订阅源"引导。
> **对应代码：** `src/pages/DailyDigest.tsx`（空状态分支，第 298-325 行）

### 场景
用户打开 DigestDesk，但今天没有任何订阅源更新。

### 流程

```
Step 1: 打开 DigestDesk
├── 首页显示："今天你的订阅源没有新内容"
├── 展示最近一期日报（可回顾）
├── 推荐操作："添加更多订阅源" / "查看归档"
└── 不发送推送通知（不打扰）
```

### 设计要点

- 没有内容时不推送（避免"空报纸"体验）
- 页面不能是空白，展示最近一期 + 推荐操作
- 这也是引导用户添加更多订阅源的机会

## Journey 6：查看历史归档 `[已完成 ✅]`

### 流程

```
Step 1: 进入归档页
├── 侧边栏或 Digest 页顶部入口
└── 展示日历视图或列表视图

Step 2: 选择日期/周次
├── 日报：按日期选择
├── 周报：按周次选择

Step 3: 查看历史 Digest
├── 完整 Digest 内容（与当时生成的一致）

```

## Journey 7：搜索发现订阅 🆕 `[已完成 ✅]`

> **当前状态：** 前后端已完整联调。搜索 Tab 默认选中，输入关键词后 300ms 防抖自动搜索，展示 Logo、名称、作者、简介。已订阅的出版物显示"已订阅" Badge。点击"订阅"按钮一键添加，Toast 反馈成功。
> **对应代码：** `src/pages/Subscriptions.tsx`（搜索 Tab UI + 防抖逻辑）、`server/src/routes/substack.ts`（搜索 API 代理）

### 场景
用户想订阅某个领域的 Newsletter，但不知道具体的 URL。

### 关键目标
**用户能通过关键词找到并订阅感兴趣的 Substack 出版物。**

### 流程

```
Step 1: 进入订阅管理页
├── 侧边栏点击"订阅源"
└── 默认打开"搜索添加" Tab

Step 2: 输入搜索关键词
├── 输入作者名："Lenny Rachitsky"
├── 或输入主题："AI Agent"
├── 或输入出版物名："Not Boring"
└── 按回车或自动触发搜索

Step 3: 浏览搜索结果
├── 展示匹配的出版物列表
├── 每个结果包含：
│   ├── Logo / 头像
│   ├── 出版物名称
│   ├── 简介描述
│   └── 订阅按钮
└── 无结果时提示"未找到匹配的出版物，试试其他关键词"

Step 4: 订阅感兴趣的出版物
├── 点击"订阅"按钮
├── Toast："订阅成功，将在下一份日报中包含"
└── 按钮变为"已订阅"状态

Step 5: 继续发现或返回
├── 继续搜索其他关键词
├── 或返回查看订阅列表
└── 或切换到 URL 添加 Tab
```

### 设计要点

- 搜索是降低订阅门槛的关键功能
- 搜索结果的 Logo 和简介帮助用户快速判断
- 搜索框应支持防抖（避免频繁请求）
- 已订阅的出版物在搜索结果中标注"已订阅"
